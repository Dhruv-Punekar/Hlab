========================================================================
DETAILED TECHNICAL DESCRIPTION: INITIAL MODULES
========================================================================

1. SYSTEM OVERVIEW
This document describes the entry point of the hardware graphics pipeline, 
specifically the memory modules that hold the initial data provided by the 
Python pre-processing scripts. This covers the Vertex Memory and Matrix 
Memory. (Master FSM and Transform Engine are excluded from this specification).

2. DATA FORMATTING
The system utilizes Fixed-Point arithmetic, bypassing the heavy resource 
cost of IEEE 754 Floating-Point modules.

2.1 Coordinate Format (Q24.8 Fixed-Point)
- Total Width: 32 bits per coordinate
- Format: Two's complement signed integer
- Precision Breakdown: 
  * 1 bit Sign
  * 23 bits Integer
  * 8 bits Fractional
- Representation: True Value = Integer Value / 256.0
- Fields per vertex: X, Y, Z, W

2.2 Color Format (RGB565)
- Total Width: 16 bits per vertex
- Breakdown:
  * Red: 5 bits
  * Green: 6 bits
  * Blue: 5 bits

2.3 Complete Vertex Word
- Total Width: 144 bits
- Packing Strategy: {X[31:0], Y[31:0], Z[31:0], W[31:0], R[4:0], G[5:0], B[4:0]}
  
3. MODULE A: VERTEX MEMORY
- Purpose: Acts as the entry buffer for the 3D pipeline. Stores the initial 
  triangle vertices generated by the Python script.
- Implementation: FPGA Block RAM (BRAM).
- Data Width: 144 bits per memory address.
- Depth: Depends on mesh size. A cube consists of 12 triangles = 36 vertices.
- Read Interface: Provides one 144-bit vertex per clock cycle when the read 
  enable signal is asserted.
- Initialization: Pre-loaded via a `.mem` or `.hex` file generated by Python.

4. MODULE B: MATRIX MEMORY
- Purpose: Stores the 4x4 Transformation Matrices (containing rotation, 
  scaling, and translation data) that will be applied to the vertices.
- Implementation: FPGA Block RAM (BRAM) or Distributed RAM.
- Matrix Format: 16 elements, each a 32-bit Q24.8 fixed-point number.
- Initial Target (Static Frame): For the very first hardware implementation, 
  this memory will hold exactly ONE static matrix loaded via a `.mem` file, 
  allowing the pipeline to successfully render a single static frame.
- Future Target (Live UART Updates): The memory will feature a Write Port 
  connected to a UART Receiver module to allow real-time matrix overwrites.

5. PYTHON SCRIPT INTERFACE
The Python script has two distinct operational modes for this project:

5.1 Offline Initialization (Phase 1 - Current Target)
1. Calculates the base 3D coordinates of the mesh (e.g., cube faces).
2. Converts coordinates to Q24.8 fixed-point integers.
3. Packs the face color into the 16-bit RGB565 format.
4. Writes the 144-bit vertex hex strings into a text file (`vertices.mem`).
5. Calculates an initial static 4x4 transformation matrix and writes it to 
   a separate hex file (`matrix.mem`) for the Matrix Memory.

5.2 Live Interactive Mode via UART (Phase 2 - Future Target)
Once the static frame rendering is proven, the script will be upgraded to:
1. Capture live user input (e.g., mouse drag on the PC).
2. Compute the new rotated 4x4 Transformation Matrix using trigonometry.
3. Convert the 16 elements into Q24.8 fixed-point formats.
4. Stream the 64 bytes (16 elements * 4 bytes) over the PC's serial port 
   (UART over USB) to the Nexys A7 board.
5. The FPGA UART receiver will catch these bytes and overwrite the Matrix 
   Memory, instantly updating the screen for the next frame in real-time.
